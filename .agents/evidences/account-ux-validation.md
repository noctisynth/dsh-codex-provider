# 账号状态与交互修正

编号：EVIDENCE-012。日期：2026-11-06。适用：DSH 0.2.2-rc.1、React 18.3.1、Windows x64。

## 观察与原因

用户在前次一般性验收之后，报告切回页面仍显示旧反馈，并提供已退出账号仍标为当前使用的截图。此前验收不覆盖这次暴露的状态组合；不保存截图中的私人资料。

代码观察：当前标记仅比较注册 ID，未检查凭据存在；注册保留是授权复用需要，但不应将其展示为仍然连接。后端保留最近登录通知，前端在非登录期间也一直呈现该通知。操作刷新依赖 busy 状态变化，存在被 React 批处理合并的可能；此项是代码推断，不能据此断言用户现场的唯一原因。

## 修正与验证

- 显式刷新序号使每次操作结束都触发状态读取；挂载、窗口 focus 和 document 恢复可见也重新读取。登录期间继续短轮询，失效读取通过 AbortSignal 丢弃。普通退出成功反馈五秒清除，未确认撤销的警告保留为错误反馈。历史成功通知不再从后端重复显示。
- 移除注册信息和授权选择项中的注册描述；账号 ID 只作为操作所需的内部标识。已退出账号显示重新登录，不出现当前使用标记。
- 紧凑分隔线列表替代独立账号卡片，移除状态胶囊；添加账号采用 shadcn Button 的 sm 尺寸。退出入口为红色文字按钮，确认弹窗为红色 destructive 按钮。
- 原生 dialog 提供模态及焦点语义，按钮使用 shadcn。依据：https://developer.mozilla.org/en-US/docs/Web/HTML/Reference/Elements/dialog 、https://ui.shadcn.com/docs/components/button 。没有引入额外弹窗库或 React DOM 实例。
- 实际打包组件验证：点击退出不发送请求，取消关闭弹窗，确认才发送请求；窗口 focus 后展示外部变化的凭据状态；不显示注册标识。Oxc tsrs 类型检查通过。
- 独立 headless Chromium 用合成账号检查深浅主题、窄布局和错误反馈；实际点击打开原生弹窗，确认 open 和 modal 均为 true，默认焦点为取消按钮。

## 安装、桌面验收与边界

用户确认完全退出 DSH 后，已通过官方插件 CLI 安装此次本地更新包。安装成功，浏览器入口、宿主入口、napi-rs 加载器、类型声明、原生模块及组件许可的 SHA-256 均与构建产物一致。

用户重新打开 DSH 后，针对新布局、退出确认与取消、切回设置后的状态及反馈更新，回复“布局和交互均正常”。据此完成此次账号 UX 修正的桌面验收；依据为用户反馈，未通过桌面自动化逐项观察，不扩展为其他平台或发布流程的验收。
