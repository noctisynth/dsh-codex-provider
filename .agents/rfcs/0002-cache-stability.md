# 会话缓存稳定性与无损重放需求

编号：RFC-002。日期：2026-11-12。状态：已授权按三个功能要求最小实施，真实缓存收益待独立验证。关联：RFC-001、SPEC-002、EVIDENCE-050、TODO-001。

## 目标与授权边界

汇总两轮缓存排查发现的协议遗漏、条件式重放缺陷和验证缺口，建立可实施、可验收的修复范围。目标是消除插件可控的缓存亲和、历史前缀及推理重放问题，并用同口径证据解释剩余差距，而不是承诺服务端永远命中缓存。

用户进一步授权以三个不同功能要求为任务阶段完成最小实现，每阶段完成相称验证、创建产品变更集并提交到本地工作区。不增加未要求功能、抽象、灵活性、配置或推测性防御；阶段命名不缩减完整需求。授权不包括真实模型请求、凭据读取或刷新、安装、推送及发布。真实请求须先确认登录路线并取得明确调用预算和凭据使用授权，既有其他任务的调用预算不挪用于本专题。

| 功能阶段 | 交付范围 |
|---|---|
| 一：会话缓存亲和 | CACHE-01 的 Codex 请求级会话头及离线线协议验证，保持现有 body key 与 SIWC 行为 |
| 二：无损输出重放 | CACHE-02、CACHE-03、CACHE-07、CACHE-09 的最小完整输出保留、有序重放、加密推理请求及编辑／旧格式一致性验证 |
| 三：历史追加更新 | CACHE-04、CACHE-05、CACHE-06 的有来源能力接入、系统／工具历史追加与检查点协调 |

CACHE-08 的同口径离线验证贯穿三个阶段；真实缓存率、套餐收益与桌面安装验收仍独立标记，不以本地提交代替。

用户观察及更正、版本、源码依据、实验记录和排除项由 EVIDENCE-050 统一维护；本需求不复写调研过程。任务优先级和完成状态只由 TODO-001 维护。

## 问题与处理范围

以下编号用于需求、方案、待办和后续验收之间的追踪，不代表它们都已被证明导致低命中率。

| 编号 | 问题 | 性质与处理边界 |
|---|---|---|
| CACHE-01 | Codex 请求缺少稳定的 Responses `session-id` 头，只有 body `prompt_cache_key` | 已确认协议遗漏，是当前首要因果验证对象；对缓存率的实际贡献未量化。SIWC 不直接套用 ChatGPT 后端契约 |
| CACHE-02 | 非空完成输出整体优先，可能覆盖先前收到的更完整推理项 | 已确认条件式资料保留缺陷；真实上游触发情况未观测 |
| CACHE-03 | 原生 output 顺序与可见块首现顺序不一致时，回放可能重排 | 已确认条件式全局顺序缺陷；不能仅凭新增后缀错误推定旧前缀每轮改变 |
| CACHE-04 | 未接入宿主系统提示的历史追加更新能力 | 已确认能力接入缺口；只在系统提示实际变化且路由、模型支持时处理，不作为固定提示低命中的既定根因 |
| CACHE-05 | 工具更新投影固定关闭历史更新，新增工具进入完整顶层声明 | 已确认能力接入缺口；工具声明真正变化时才触发，不能声称每步都会破坏缓存 |
| CACHE-06 | 外层或旧输入改变会重建推理检查点，既有档位更新不再继承 | 已确认现有行为，需要与历史追加机制协调；固定 High 且从无更新项时不据此归因，也不取消合法的失配校验 |
| CACHE-07 | 加密推理请求参数与实际接收、保存、重放缺少路线级闭环 | 社区显式请求与本插件默认行为存在差异，但实际漏传尚未证明；先验证公开 API 与 Codex 后端各自行为，不把文档默认值等同于后端实测 |
| CACHE-08 | 既有测试证明参数接受和工具续接，未证明暖缓存收益及完整前缀一致性 | 已确认验收证据缺口；补齐可重现、同口径、受预算约束的验证 |
| CACHE-09 | 可见 assistant 内容编辑后，旧 raw replay 是否可靠失效尚未闭环 | 待核实一致性边界，不预先认定宿主已发生编辑后错误回放；先验证，再决定所需最小修复 |

## 功能要求

### 会话身份与路由：CACHE-01

- Codex 浏览器和设备码路线按同一后端契约传递稳定的缓存亲和身份；同一持久会话跨工具续接、后续用户轮次与正常恢复不随机变化，不同会话不得被任意合并。
- `session-id` 与 body `prompt_cache_key` 分开表达和验证。保留现有 body key 的稳定派生，不把“参数已接受”当作“亲和路由或收益已验证”。
- 不使用令牌、账号资料、请求次数或时间作为会话身份，不新增 ID 存储和用户开关；无正式会话身份的辅助调用不伪造会话。
- SIWC 保持独立支持判断，不因 Codex 源码存在某个请求头就向其公开接口盲目附加。

### 输出完整性与历史一致性：CACHE-02、CACHE-03、CACHE-07、CACHE-09

- 已收到的完整原生输出不得仅因完成通知非空就被更少资料覆盖。完整完成通知、稀疏完成通知、空完成通知都必须保留有效输出及加密推理资料。
- 原生输出按协议全局顺序回放，不由 UI 内容块的首现顺序重新决定。保留调用关联、原始参数、消息 phase、搜索项和不可见推理项，不以显示摘要冒充加密推理。
- 可见内容与 raw replay 不一致时，不能用旧 raw 项悄悄覆盖编辑结果，也不能把已丢失的加密内容或历史顺序伪造回来。
- 兼容已保存的旧会话；新格式、旧格式和缺失或空重放资料分别验收。来源不一致、合法历史编辑和显式压缩不得被误判为可原样复用。
- 只有成功完成才产生成功重放资料；取消、断流、失败和协议冲突沿用明确的错误与终止边界。

### 前缀保持与能力边界：CACHE-04、CACHE-05、CACHE-06

- 对已验证支持的路线与模型，系统提示变化和工具新增采用宿主正式的历史更新能力，避免改写已经发送的前缀；不支持的组合维持明确的全量投影行为。
- 工具更新必须保留声明、延迟加载、启用位置及后续回放的完整关系。不能只打开模型元数据，而让适配器仍删掉更新消息或让原生层拒绝更新项。
- 需要改变旧历史的编辑、工具移除或重声明、模型或账号切换、摘要压缩，允许使缓存或检查点失效，但必须保持语义正确。不为命中率忽略用户选择或保留过时工具权限。
- 推理配置更新保留有效基线与原始位置；合法失配仍重建基线。SIWC 既有不支持边界不因本专题而静默放开。

## 验收要求

| 验收项 | 必须证明的结果 |
|---|---|
| 路由身份 | 原生线请求实际携带预期身份；同会话稳定、新会话隔离、恢复一致；body key 与 header 分别验证 |
| 完成事件 | done 完整而 completed 稀疏、completed 补齐资料、completed 空数组、双方完整等场景不丢项、不丢加密内容、不重复 |
| 全局顺序 | 非空 reasoning summary、交错输出、一个原生项对应多块和无可见块的输出，经宿主组装、持久化和恢复后仍保持原生项顺序 |
| 可见内容 | 文本和工具参数编辑、块删除、来源变化时旧重放的复用或失效符合已确认规则，不回放过期正文 |
| 固定设置 | 固定 6.1 Sol / High、未切模切档，旧输入不变时，证明下一请求保留此前已发送前缀；不要只比对 UI 文本 |
| 历史更新 | 支持组合的提示更新和工具新增位于历史尾部，基线声明不被重写；不支持组合不发送非法项，工具移除不扩大可执行范围 |
| 配置协同 | 固定 High 不生成更新；真实切档保留合法更新位置；编辑、截断、账号或模型变化按规则失效 |
| 用量口径 | 单请求读取率使用服务端 `cached_tokens / input_tokens`；会话率累计分子分母后相除。读取、写入、普通输入互斥，推理不重复计入输出 |
| 因果与收益 | 同账号路线、模型、effort、传输、搜索、输入和统计口径做对照；区分冷启动与暖请求，报告绝对用量、比例和限制，不能仅以请求成功验收 |

真实收益验证应覆盖用户报告的短、长会话及短、长间隔，并把冷启动、恢复和显式压缩后的请求分开记录。较短样本也必须确认复用前缀是否满足所测模型的缓存资格；“会话较短”不自动等于“应有缓存”。

社区 95%–97% 是用户观察的参照，不是对任意输入、登录路线或服务端状态的无条件承诺。对照接受阈值和调用预算须在实验前确认；若修复后仍有差距，应记录未闭合条件，不能以离线通过或一次偶然命中宣告长期收益验收。

## 非目标与保留边界

- 不以此任务引入 WebSocket、预热请求、缓存 TTL 开关、云端压缩、Fast 档或新的客户端传输框架。
- 不同时调整 `originator`、Beta、verbosity、工具 strict 等差异来冒充单变量验证；没有缓存用途证据的头不作为必修项。
- 不盲补 `x-codex-turn-state`，不跨用户轮次保存或重放服务端 turn token。社区与本插件均缺少它，不作为双方差距的既定解释。
- 不改宿主统计界面，不回填旧统计、不虚报命中、不为提高比例删除应发送的上下文或降低思考强度。
- 不重做已验证的 body key 算法和互斥用量桶，也不把本专题等同于既有输出吞吐排查。两类现象可能有关，但因果须各自验证。
