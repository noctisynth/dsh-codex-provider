# 会话缓存稳定性与无损重放技术方案

编号：SPEC-002。日期：2026-11-12。依据：RFC-002。状态：按三个功能阶段最小实施，真实缓存收益另行验证。证据：EVIDENCE-050。任务及优先级：TODO-001。

## 职责与设计原则

本专题补充 SPEC-001，不替代现有 Rust 核心、napi-rs、TypeScript 宿主适配、凭据事务和 DSH 历史所有权。以下为目标实现，不表示当前产物已具备这些行为。现状、源码定位及调查纠正只记录在 EVIDENCE-050。

| 责任层 | 本专题职责 |
|---|---|
| 宿主适配与模型映射 | 透传正式会话身份，按经过验证的精确能力选择投影，保留工具历史与消息来源 |
| Rust 请求转换 | 构造稳定线请求，保留独立亲和元数据，转换历史更新并校验重放内容 |
| Rust HTTP 传输 | 仅向适用后端添加会话亲和头，不改变认证、端点或重试语义 |
| Rust SSE 事件与重放 | 合并完整输出、保留加密资料、建立与 UI 顺序无关的原生输出顺序 |
| 既有 DSH 宿主 | 继续拥有会话 ID、消息持久化、工具权限、预算及压缩；不修改宿主代码 |
| 验证与证据 | 只采集必要的结构、摘要、计数与用量；真实调用遵守另行确认的授权和预算 |

不引入通用请求参数透传、缓存服务、第二套会话存储、全局正文副本或可配置兼容框架。现有 body key 与用量桶保持不变，先隔离单变量再验证产品集成。

## 1. 会话亲和元数据：CACHE-01

### 数据流

1. TypeScript 沿用正式 `GenerateOptions.sessionId`，不产生额外身份。
2. Rust 请求转换沿用现有固定长度派生值，不改变已安装算法的编码和值。
3. 通过最小内部访问器把该值供给传输层，当前 body 与 header 共用同一稳定值，不复制原始会话身份、不新增状态。body 字段与请求级 header 分别构造和验证，不依赖重新解析序列化 body。
4. Codex 浏览器与设备码路线发送 `session-id`。目标值采用同一会话的稳定派生值，不要求泄露原始 DSH ID；该选择的后端接受性在受控对照及产品集成中验证。
5. 缺失或空会话 ID 时，两种会话元数据均省略，不随机生成、不从账号或时间回退。SIWC 默认维持现有请求头，未有独立依据和验证前不应用 Codex 专属契约。

`session-id` 采用请求级头，不写进共享 HTTP 客户端默认头，防止并发会话互相覆盖。账号认证仍来自当前请求的正式凭据记录，不进入亲和 ID 派生。辅助请求有无正式身份按各自产生者处理，不用主会话身份填充没有 ID 的调用。

### 最小验证

离线覆盖同会话多轮、工具续接、重建适配器、恢复、不同会话、并发请求及无 ID。检查最终 HTTP 请求头，而不只检查 N-API 入口或 body key。两条 legacy 方式共用契约，SIWC 保持不变；不记录真实 ID、账号或令牌。

真实因果筛查先保持同一接收实现和其他请求字段不变，只改变 `session-id` 是否存在。不要同时补 `x-client-request-id`、改 `originator`、Beta、verbosity、include 或传输。其后再经正式原生与宿主链路验证，不以诊断脚本代替产品验收。

## 2. 完成事件的完整性合并：CACHE-02、CACHE-07

### 收集与权威来源

- 沿用 `output_index` 收集成功的 `output_item.done`，同时保存项目 ID、类型及原生内容。
- `response.completed.output` 不再以“非空”作为全量完整性的充分条件。按项目身份与索引同 done 集合对齐：完成数组中的完整项目采用最终态，缺失字段由同一项目的已完成资料补齐，完成数组省略的有效 done 项仍保留。
- 加密内容的非空值不得被字段缺失、null 或空值覆盖；不能只保留摘要或 ID，就宣称保存了加密推理。
- 最终输出使用协议全局顺序，去除同一项目的重复引用。不得仅按 `call_id` 合并不同输出，也不得用 UI 块位置猜测原生项目身份。
- 项目类型、身份或最终正文发生真实冲突时，沿用既有协议错误边界，不增加静默重试或凭空合成项目。两个不同非空加密值的权威规则须先核对事件契约与实际样本，再明确测试和处理，不在未经验证时臆定优先级。

合并完成后，同一有序集合同时用于重放和成功推理检查点的输出摘要，避免两者各用一份不同的“最终输出”。错误、取消和未完成的响应不建立成功检查点。

### 显式请求与实际回传分开验证

为支持 stateless 推理的适用路线构造去重的 `include` 列表，包含 `reasoning.encrypted_content`，同时保留已有网页搜索来源请求。按路线验证支持后再开放，不从公开 API 的默认行为推断 Codex 后端一定回传，也不从加上 include 推断重放已经正确。

验证分别记录 done、completed、合并结果和下一请求是否含加密字段的布尔值、项数及顺序摘要；不保存或打印加密载荷。若真实响应未发生稀疏覆盖，只能报告离线缺陷已覆盖，不能报告真实低命中的原因已复现。

## 3. 原生顺序与可见内容解耦：CACHE-03、CACHE-09

### 新重放格式

目标采用版本化的响应级重放：单一有序 `items` 集合作为原生回放的权威来源，顺序来自协议 `output_index` 或已核实的完整最终顺序，而不是可见块首现顺序。可见块仍按宿主流契约提供展示，不为修复回放而改变实时显示顺序。

响应级元数据保存格式版本、有序原生项及既有推理检查点；是否另存可见内容校验摘要，由正式编辑／投影入口的失效保证核验结果决定，不把待核实边界直接扩展为必需字段。避免同时在响应级和每块中复制整份原生项目；若元数据已经独立于块结构，利用正式 ReplayEnvelope 可省略逐块数据的契约，不建立第二套持久化系统。

优先复用宿主已证明有效的重放失效契约。若它不足以覆盖响应级资料，再加入最小可见摘要：以同一 Rust 规范化逻辑覆盖块类型、文本、调用 ID、工具名及原始参数字符串，不掺入时间、消息 ID、用量或其他请求级状态；在输出结束时生成，下一次读取该条消息时校验。正文与重放不匹配时，尊重宿主保留的当前可见内容，不让旧 raw 项覆盖编辑结果，不再沿用无法验证的加密推理及相关检查点。验证同时避免误伤无语义变化的正常恢复。

### 兼容与失效

- 新写入格式有明确版本；旧版逐块及 trailing 格式保留读取能力，不批量迁移或修改历史会话。
- 旧格式能由已有资料验证的内容继续使用；对已经丢失的全局顺序、加密载荷或编辑前状态，不声称可以恢复。不能安全复用时，按现有可见内容降级，明确此为重放失效，不伪造 provider 项。
- 空重放快照继续遵循已有 fallback，不吞掉可见文本和调用。
- 账号／模型来源、显式编辑、压缩和截断保持原有一致性校验；不能为了命中率忽略来源变化。

回归须经原生 Mapper、正式 BlockAssembler、消息保存及恢复走完整闭环，特别覆盖非空推理摘要、交错事件、一个原生项对应多块、无可见内容的项目、工具续接及搜索引用。

## 4. 系统与工具的历史更新：CACHE-04、CACHE-05

### 能力来源

路由能力与模型能力共同约束接入。只使用有来源并经过验证的精确组合；目录字段缺失时，需先确定最小且可维护的能力映射，不从型号命名或社区继承的 compat 直接推导官方授权。不引入启动自动探测、额外模型调用或复制整套 Pi 模型目录。

能力映射、投影、原生转换和真实协议验证必须一起闭合后，才向宿主声明 `systemPromptUpdate: 'in-history'` 或 `toolUpdate: 'addition-only'`。不只加标记，也不一概对 SIWC 或所有目录模型开放。

### 系统提示

保留初始提示的表示与位置，后续系统更新采用已验证协议对应的历史消息，不把每次最新提示移回初始 `instructions` 或替换历史首项。宿主声明的“完整替换提示”语义必须被模型理解；必要的更新指令由已确认协议表达，不靠忽略旧权限或手工拼接所有新旧提示实现。

时间和运行上下文原有 user 消息追加继续保留，不改成重写系统消息。固定系统内容时不生成无意义更新。

### 工具新增、移除与重声明

使用宿主正式 `toolHistory` 和 `projectToolUpdates`。新增工具延迟声明，不让它提前进入初始模型可见工具列表；原生层将对应历史新增项转换为经过验证的 `additional_tools` 表示，并在后续请求中保留原位置与内容。

只有已声明、按历史启用的工具才可被调用。工具移除或同名 schema 变化不假装是新增：按 `addition-only` 的实际支持边界及当前有效工具集处理，必要时允许前缀和检查点失效。DSH 工具执行与权限判断继续有效，不能为了缓存保留已被移除工具的执行权限。

内置搜索、工具排列、参数 schema 和图片精度等也属于需比较的请求 surface；本专题不顺带改变它们的默认值。

## 5. 推理检查点协调：CACHE-06

检查点继续校验账号作用域、模型、请求外层和精确历史，不取消这些语义边界。已验证为纯追加的系统与工具更新，应只延长历史，不无故改写基线工具、初始提示或既有 `configuration_update`。

固定 High 且从无切档时，检查点有效或失效都不生成更新项，不把这种重新建立相同基线的行为当作前缀损坏。存在真实切档时，历史更新仍在原始位置回放；内容编辑、摘要截断、模型或账号变化继续按规则重建基线。新重放格式与检查点的输入、输出摘要统一生成，不能分别使用显示顺序与原生顺序。

SIWC 继续禁止现有不支持的配置更新输入；本专题不解除 EVIDENCE-032 记录的限制。未来若需把已选 effort 的历史与可复用检查点进一步分离，须先证明最小方案的语义与必要性，不先建立新状态机。

## 6. 验证与因果归属：CACHE-08

### 离线不变量

固定旧消息、来源、工具、系统提示、图片策略和 High 时，比较完整最终线请求：下一请求的已有 `input` 前缀与上一请求逐项一致，影响渲染的外层设置不变。内部校验摘要变化不等于线请求变化；新增输出的后缀错误也不自动证明旧前缀被重写。

本地通过只能证明序列化与回放一致，不能证明服务端实际 rendered context、缓存资格、缓存路由或 KV 复用。

### 真实实验顺序与约束

1. 先确认用户复现采用的登录路线、社区传输设置和单轮／累计展示口径；未确认前不补写为已知条件。
2. 经另行授权，使用非私密合成输入、固定 6.1 Sol / High、固定搜索／工具／SSE 条件，确认可复用前缀具备所测模型的缓存资格。活动凭据只在内存使用；过期或需要迁移／刷新时停止，不自行扩大权限或调用预算。
3. 第一组只验证 `session-id`。可先做每臂预热加重复请求的四次筛查；这个建议不是当前授权，也不是统计显著性保证。按预先约定的独立缓存分组和执行顺序避免串用预热结果；必要时另行批准反向顺序复核。
4. 第二组再独立验证 include 与完整项目回传；随后验证修复后的合并和重放。不要把多个改动合并后只报告一次较高命中。
5. 产品链路验收再覆盖工具续接、跨用户轮次、恢复、短长历史与时间间隔，以及支持组合中的系统／工具更新和切档。高用量矩阵按预算执行，不自动展开。

只保留实验组标记、版本、路线类型、请求与前缀结构摘要、首个差异位置、项目计数、加密字段存在性、输入／读取／写入／输出 token、必要时间与公开错误码。摘要只在受控合成数据范围内记录；不保存正文、原始会话 ID、账号标识、设备标识、令牌或加密推理载荷。

单轮读取率为 `cached_tokens / input_tokens`；累计率为 `sum(cached_tokens) / sum(input_tokens)`，零分母标记不可计算而非高命中。冷启动单列，reasoning 是输出子集，cache write 不重复计入普通输入。
